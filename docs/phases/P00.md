# P00 — Clean-room bootstrap, threat model & reproducibility

**Depends on:** none. **Expected terminal gate:** `BOOTSTRAP_READY or BLOCKED_ENV`. **Mode:** autonomous local development; no payment, account creation or real trades.

## Research jobs (agent: researcher)

- R1. Read `AGENTS.md`, `docs/10_EVIDENCE_LOG.md`, and prior phase reports; restate target, hard boundaries and unknowns for P00.
- R2. Revisit first-party documentation for any changing API or software claim; save dated URLs, snippets/hashes and contradiction notes; never trust old assumptions as wire facts.
- R3. Inventory existing code/tests that can be reused within this clean repo; avoid old project imports.

## Plan jobs (agent: planner)

- PL1. Decompose jobs below into atomic changes (<1 logical concern / commit). For every job list touched files, input artifact, output fixture, test and rollback.
- PL2. Mark all network or paid-inference jobs with their permission and schema prerequisite; do not let them become blockers for independent offline work.
- PL3. Declare measurable acceptance gates and no-go constraints before writing changes.

## Execution jobs (agent: executor)

- E1. Inventory only the new repository; document clean-room exclusions and relevant research hypotheses without importing old code.
- E2. Check Node/SQLite readiness, run existing tests and synthetic demo. Save exact command output with UTC date and Git hash.
- E3. Verify .gitignore excludes .env, SQLite WAL, logs; create initial local repo, atomic baseline commit if Git available.
- E4. Read current GSD command list; initialize `.planning/` non-destructively and record known phases, requirements and project state.
- E5. Freeze V0 target definition, NO-WALLET invariant, API egress allowlist and spending limits.

## Audit jobs (agent: auditor)

- A1. Inspect every changed file for unintended network hosts, secret/key leakage, transaction capability, target leakage, historical/live confusion or logical defects.
- A2. Compare implementation and stored fixtures against official contracts; distinguish actual observations from examples.
- A3. Check test independence: mock responses can validate parsers but cannot certify real provider functionality.

## Verification jobs (agent: verifier)

- V1. Run `npm test`, `npm run demo`, `npm run doctor` and any phase-specific fixture checks; capture stdout, exit status and date in a phase report.
- V2. Run negative tests before positive tests: missing key, 429, stale feed, broken WS, late inference, duplicate rounds and adversarial timestamps where applicable.
- V3. Verify exact gates:

  - New repo checks pass; no real execution code or secrets; `npm test`, `npm run demo`, `npm run doctor` succeed offline.
  - `.planning/STATE.md` clearly distinguishes IMPLEMENTED/OFFLINE_VERIFIED from LIVE_UNVERIFIED.

## Repair jobs (agent: repairer)

- FIX1. Cluster root causes and repair one at a time, creating a regression test for each confirmed defect.
- FIX2. Re-run audit + verification after each fix; maximum **three bounded iterations** per failure class; no infinite network retries.
- FIX3. If still failing, mark BLOCKED with evidence and proceed only to unrelated offline work; NEVER lower a safety test merely to turn gate green.

## Required artifacts / exit checklist

- `docs/phases/P00_REPORT.md` with date, code commit hash, Research/Plan/Execute/Audit/Verify/Repair details, test log excerpt and truthfully chosen gate status.
- Updated `.planning/STATE.md` and task board; a local atomic commit if repository is initialized.
- Fixtures and hashes saved under `research/fixtures` or `var/` (raw private data stays ignored).
- Explicit list of fields/APIs still unknown and recommended next verified step.

**Next phase only after:** `BOOTSTRAP_READY or BLOCKED_ENV` or a clearly declared partial/blocked transfer permitted by dependency graph.
